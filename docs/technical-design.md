# 技术设计

## 业务闭环

重点公众号文章入库 -> 资源抽取与聚合 -> 质量评分 -> 用户关键词搜索 -> 资源详情追溯 -> 订阅追踪 -> 站内/飞书通知。

## 数据对象

- `source_accounts`: 公众号来源、可信度、采集状态。
- `articles`: 标准化后的公众号文章。
- `resources`: 聚合后的资源实体。
- `resource_mentions`: 文章与资源的提及关系和证据片段。
- `resource_scores`: 可拆解评分历史。
- `status_checks`: 资源状态时间线。
- `subscriptions`: 主题、资源、来源订阅。
- `notifications`: 站内与外部通知记录。
- `manual_reviews`: 人工修正记录。
- `task_logs`: 导入、抽取、评分、通知等任务记录。

## API 边界

用户侧 API 聚焦搜索、详情、订阅、通知；管理侧 API 聚焦来源、历史文章导入、人工修正与重算评分。采集工具不直接写业务表，必须先转换为标准文章对象。

## MVP 降级

若真实采集工具不可用，P0 仍可通过 JSON 冷启动导入完成：文章入库、资源抽取、搜索、评分、来源追溯和订阅通知。
